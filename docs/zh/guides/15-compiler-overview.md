# 15 编译原理速览

这一章不讲怎么实现编译器，只讲清楚：你写的 Aero 代码，到底经历了什么才变成可执行文件。看完你对"为什么 Aero 快""为什么有些错误在编译期就报"会有具体的感觉。

## 流水线

```
源码 → 词法分析 → 语法分析 → HIR（名称解析 + 类型推断 + 借用检查）→ LLVM IR → 机器码
```

## 第一步：词法分析（Lex）

把字符串切成"单词"（token）。`let x = 1;` 被切成 `let`、`x`、`=`、`1`、`;`。这一步不管语法对不对，只负责切分。字符串、数字、标识符、运算符、括号都是 token。

## 第二步：语法分析（Parse）

按文法把 token 组装成树（AST）。`1 + 2 * 3` 在这里变成一棵"乘法在加法下面"的树，对应运算符优先级。这阶段能抓到的错误就是"语法错误"——比如漏分号、括号不匹配。

## 第三步：HIR 与类型推断

这是 Aero 的核心。AST 被转成 HIR（高层中间表示），同时做三件事：

1. **名称解析**：`x` 到底指哪个变量，`max` 是哪个函数，全部对上号。这个阶段抓"未定义变量""函数重复定义"。
2. **类型推断**：你写 `let x = 1 + 2;` 不写类型，编译器在编译期把类型推出来——它是 `i64`。这就是白皮书说的"0.1 毫秒推导出 64 位整型"。类型不对（比如把 i64 塞给 i32）在这里被拦下。
3. **借用检查**：第 9 章那套借用规则，在这里验证。借用冲突编译不过，程序根本生不出来。

错误消息里阶段名（`[词法分析]`、`[语法分析]`、`[类型]`、`[借用检查]`、`[代码生成]`）指的就是你在流水线的哪一步被拦下。

## 第四步：LLVM IR

HIR 被翻译成 LLVM 的中间表示（IR）。IR 是一种"接近机器码但还带类型和变量"的格式。Aero 自己只写到这一步，剩下交给 LLVM——这就是"不造底层轮子"原则：机器码生成、寄存器分配、指令调度，LLVM 已经做了几十年，质量远超自己写。

## 第五步：优化与机器码

LLVM 对 IR 跑优化（Aero 用的是 O2 级别的 pass），比如把没用的变量删掉、把循环优化、把常量算好。然后针对你的 CPU 生成机器码。

这一步解释了前言的问题：为什么 Aero 程序比 Python 快？因为类型在第三步就定死了，LLVM 能生成高效的机器码；Python 的类型检查和对象管理都发生在运行时，每行代码都要付账。

## JIT 和 AOT：两种收尾方式

优化完的 IR，两条路：

- **JIT**（`aero run`）：LLVM 在内存里直接把机器码编译出来，立刻执行。好处快，坏处程序没法脱离编译器。
- **AOT**（`aero build`）：LLVM 把机器码写进一个目标文件（.obj），再调用 gcc 把 CRT 启动代码、库和你程序的机器码链接成独立 .exe。

## 一个程序的完整旅程

```
hello.aero
  → 词法：切成 print ( "Hello" \n ) ;
  → 语法：AST：调用 print，参数是字符串
  → HIR：print 是内建函数，参数类型 str
  → 类型推断：字符串字面量是 str，OK
  → 借用检查：没有借用，OK
  → LLVM IR：生成调用 printf 的指令
  → 优化：把常量折叠好
  → AOT：写出 .obj，gcc 链接成 hello.exe
```

从源码到能跑的 exe，就是这么一条线。你现在对"编译器"三个字有画面了。
