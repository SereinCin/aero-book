# 09 引用与借用

## 问题：函数改不了外面的变量

第 5 章讲过，函数参数是拷贝的：

```aero
fn bump(n: i64) {
    n = n + 1;   // 改的是拷贝
}

let x = 10;
bump(x);
print(x);   // 10，没变
```

想让 `bump` 真正把 `x` 改成 11，Aero 的办法是**引用**。

## 引用：变量的另一个名字

```aero
fn bump(r: &mut i64) {
    *r = *r + 1;   // *r 就是"r 指的那个变量"
}

let mut x = 10;   // 注意：要被可变借用，x 得声明成 mut
bump(&mut x);
print(x);   // 11，真的改了
```

拆开看：

- `&mut x`：取 x 的可变引用（"借走 x 的修改权"）。
- `&mut i64`：参数类型是"可变 i64 引用"。
- `*r`：解引用，读写 r 指向的变量。

引用是 Aero 里唯一能"间接修改外部变量"的机制。它本质是个地址，但编译器盯着它，防止你借出问题。

## 读引用：不可变借用

```aero
fn peek(r: &i64) {
    print("%d\n", *r);
}

let x = 42;
peek(&x);   // 42
```

`&x` 是不可变借用：只能读，不能写。

## 借用规则（借书的比喻）

把变量想成一本书：

1. **可以同时借出很多本"只读副本"**——多个 `&x` 共存没问题，大家只读不写。
2. **"可写借出"一次只能一个人**——`&mut x` 借出期间，不能再有别的借用。
3. **只读借用期间，不能借出可写**——有人正读着，你不能同时让人改写。
4. **借用期间不能动书**——借用存活时，源变量本身不能重新赋值（赋值算写入）。

违反任何一条，编译直接报错，程序都编译不出来：

```aero
let x = 10;
let r1 = &x;
let r2 = &x;      // OK，多个只读借用

// let r3 = &mut x;   // 错误：已有只读借用，不能再可变借用
// x = 20;            // 错误：r1 还活着，不能写 x
print(*r1);
```

这条规则把"悬垂指针"和"数据竞争"这类最阴险的 bug 在编译期就消灭了。

## 借用什么时候结束：NLL

借用不是"活到变量作用域结束"，而是活到**最后一次使用**。这个规则叫 NLL（Non-Lexical Lifetimes，非词法生命周期）。

```aero
let x = 10;
let r = &x;
print(*r);   // r 最后一次使用在这
x = 20;      // OK！r 已经结束了，现在可以写 x
print(x);
```

看着是不是违反第 4 条？没有——`print(*r)` 之后 `r` 就"还书"了，借用结束，后面随便写。**借用只活到它最后一次被使用的地方**，这是 Aero 借用检查器最实用的特性。

## 借用目标必须是变量

```aero
// let r = &(1 + 2);   // 错误：借用目标必须是变量
```

引用必须指向一个真实存在的变量，不能指向临时表达式（临时值借出去就没了）。

## 引用的引用？先别想

Aero 0.1 的借用系统是精简版：支持单层 `&T` / `&mut T`，**不支持**引用套引用、引用存数组、引用作为返回值这些高级玩法。别硬写，编译器会告诉你哪些不行。这套系统的完整版（更接近 Rust 的借用检查）在路线图上，0.1 先保证最常用场景好用。

## 练习

1. 写 `swap(a: &mut i64, b: &mut i64)` 交换两个变量的值，用 `let x = 1; let y = 2; swap(&mut x, &mut y);` 验证。
2. 写 `increment_all` 用引用给数组的每个元素 +1（提示：`let mut i = 0; while (i < 3) { arr[i] = arr[i] + 1; ... }`，这题不用引用也行——想想为什么）。
3. 故意写一段"借用期间写源变量"的代码，看编译错误信息长什么样。
4. 验证 NLL：`let r = &x; print(*r); x = 100;` 能编译吗？`let r = &x; print(*r);` 后面加一句 `x = 100;` 呢？
